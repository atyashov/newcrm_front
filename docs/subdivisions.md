# Subdivisions

`subdivision` в проекте — это глобальный рабочий контекст приложения.

По смыслу это похоже на переключение между магазинами в OpenCart:
- один и тот же раздел может показывать разные данные в зависимости от выбранного `subdivision`
- от текущего `subdivision` зависят товары, категории, клиенты, кассы, сметы и другие сущности

## Главная идея

`subdivision` не является просто фильтром страницы.

Это общее состояние приложения:
- пользователь может выбрать подразделение в шапке
- выбор сохраняется между перезагрузками
- многие запросы на бэкенд должны учитывать этот выбор

При этом `subdivision` может быть **не выбран**.

Это валидный режим для:
- администрирования
- аналитики
- разделов, где данные не обязаны быть привязаны к одному подразделению

## Где хранится состояние

Источник истины — Vuex модуль:
- [subdivisions.js](/D:/OSPanel/home/crm-frontend/src/store/modules/subdivisions.js)

В нем хранятся:
- список подразделений
- текущий `currentId`
- статус инициализации

`localStorage` используется только для восстановления выбора после перезагрузки.

То есть:
- store — главный источник текущего значения
- `localStorage` — вспомогательное хранилище

## Как работает выбор подразделения

При старте приложения:
1. грузится список подразделений
2. читается `subdivision` из `localStorage`
3. если он валиден и существует в списке — становится текущим
4. если невалиден — очищается
5. если ничего не выбрано — приложение работает с `currentId = null`

## Правило для запросов на бэкенд

`subdivision_id` нельзя передавать “на всякий случай”.

Правильная модель такая:
- если подразделение выбрано, запрос уходит **с** `subdivision_id`
- если подразделение не выбрано, запрос уходит **без** `subdivision_id`

То есть нельзя строить запрос вида:
- `subdivision_id: undefined`
- `subdivision_id: null`

Нужно делать явное ветвление:
- либо вызвать сервис с параметрами
- либо вызвать его без параметров вообще

## Пример правильного вызова

Для получения категории:

```js
const response = props.subdivisionId
  ? await fetchCategoryById(props.categoryId, {
      subdivision_id: props.subdivisionId,
    })
  : await fetchCategoryById(props.categoryId)
```

Идея здесь в том, что сервис не должен угадывать глобальный контекст сам.

Контекст известен в точке вызова:
- страница
- модалка
- action

Поэтому `subdivision_id` передается туда явно.

## Что важно помнить дальше

- `subdivision` — это глобальный контекст, а не локальный фильтр
- `null` для него допустим
- `localStorage` не источник истины
- `subdivision_id` добавляется в запрос только если есть выбранное подразделение
- если подразделение не выбрано, параметр в запрос вообще не отправляется
