# Вкладки смет: подключение фронтенда

Реализованы на dashboard внутри Outlays.vue. Основной список и финансовый график
сохранены. Вкладки создаются при первом открытии; переключение сохраняет фильтры,
страницу и загруженные строки. При смене подразделения старые ответы новых
списков игнорируются. После быстрых изменений загруженные таблицы обновляются.

- Поступления и операции: серверная пагинация, сортировка, фильтры, итоги всей
  выборки; просмотр/редактирование связанной сметы.
- Распределение и самовывоз/самовозврат: независимые таблицы заказов и возвратов
  на текущий локальный календарный день; фильтры сотрудников, складов, статусов.
- Возвраты: период по return_date, независимо от даты заказа.
- Клик по статусу/сотрудникам открывает быструю форму PATCH, без полной сметы.
- Текст: по кнопке загружаются все страницы заказов и возвратов за период,
  события объединяются по времени. Есть копирование и ручное выделение текста.
- В полную форму добавлены self_pickup, self_return, return_date_comment.

## Обнаруженные изменения контракта

1. ListOutlaysRequest ограничивает page_size максимумом 100. Ранее фронт запрашивал
   500. Теперь основной список по умолчанию 100, селекты предлагают 20/50/100.
   Если бизнесу нужны 500, сначала увеличить лимит сервера.
2. Несмотря на описание «булевы статусы по складам», фактическая реализация
   хранит флаги в outlay_item_stages по позициям. stores[].stages возвращает
   числовые счётчики. Фронт только отображает плашки готовности и не отправляет
   несуществующее переключение всего склада. Редактор флагов позиций не входит
   в текущую реализацию вкладок.
3. Сервер документирует UTC для дат без смещения. Фронт отображает полученное
   время без преобразования в часовой пояс браузера. «Сегодня» берётся локально,
   как у остальных календарных полей приложения. Нужный бизнес-часовой пояс
   следует отдельно согласовать с сервером.

Финансовый график использует период фильтра основного списка смет. Новые вкладки
имеют собственные периоды (изначально копируют его), а день распределения от него
не зависит. При изменении периода основного списка новые периоды синхронизируются.

Клиентские проверки не заменяют серверную авторизацию. Списки сотрудников для
назначений фильтруются по активному статусу и подразделению сметы; окончательную
допустимость каждого назначения проверяет сервер. Ошибки показываются в модалке.
