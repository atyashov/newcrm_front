# Документы и просмотр сметы

## Размещение элементов

- PDF за период: рядом с фильтрами списка смет, как в legacy _search.php.
  Использует даты заказа от/до и выбранное подразделение. Другие фильтры списка
  не передаются: сервер их в этом отчёте не поддерживает. Пагинация не влияет на PDF.
- Документы одной сметы: после кнопок сохранения в редактировании, в просмотре
  (модалке) и на странице внутренней информации, как в legacy _form.php/view.php/info.php.
- Иконки информации и клиентского просмотра: рядом с действиями в основном
  списке и рабочих вкладках. Не создают запрос на документы для каждой строки.

## Страницы

- /outlays/:id/info: авторизованная информация; контрагент, состав сметы,
  сотрудники, кассы, документы, копирование и перевыпуск публичной ссылки.
- /outlay/:uuid: публичная смета; также принимается /outlay/show/:uuid.
  Это адрес фронтенда, не публичный JSON-адрес API.
- Публичная страница запускается отдельным корневым компонентом и роутером.
  У гостя нет /user, загрузки подразделений, меню и перенаправления на login.
  Если есть локальный токен, отдельно проверяются /user и право чтения info сметы.
  Только после успешных проверок отображаются сведения и действия сотрудника.
  Существующий токен администратора при просмотре публичной ссылки сохраняется.
- Внешние ссылки с админки открывают публичный маршрут полной навигацией,
  чтобы использовался именно публичный режим приложения.

## Скачивание и безопасность

- Генерация документов возвращает binary attachment. Скачивание через Axios blob
  с актуальным Bearer из localStorage, затем временный Object URL с очисткой.
- Не использовать прямой href на защищённый API и не помещать токен в query string.
- URL загрузки строится по известному API и типу документа, не берётся произвольно
  из каталога сервера. Имена файлов очищаются от управляющих символов/путей.
- Ошибки JSON внутри Blob (422/403/503/429) разбираются и показываются в интерфейсе.
- Публичный API вызывается отдельным Axios instance без Authorization и credentials.
  Проверка сотрудника на этом экране использует явно переданный Bearer только
  в /user и защищённом info; UUID-запрос остаётся без авторизации.
- Описания/другой серверный текст не выводятся через v-html. Изображения и внешние
  ссылки допускают только HTTP(S). Изображения имеют referrerpolicy=no-referrer.
- В index.html referrer=no-referrer устанавливается до внешних ресурсов;
  публичный запуск дополнительно устанавливает robots=noindex,nofollow.
- На хостинге фронтенда также рекомендуется выставить для /outlay/* заголовки
  Cache-Control: private, no-store; X-Robots-Tag: noindex, nofollow;
  Referrer-Policy: no-referrer. Не кэшировать публичные ответы сервис-воркером/CDN.
- Перевыпуск ссылки требует подтверждения: прежняя ссылка сразу перестаёт работать.

## Ограничения сервера, не заменённые заглушками

- subdivision.description показывается в правой части шапки безопасным текстом.
  HTML-разметка не исполняется. Цвета обоих экранов просмотра используют общие
  SCSS-переменные темы, как основной раздел смет.
- Печать доступна всем. В печать не попадают кнопки и внутренний блок сотрудников.
  Сотрудникам доступны редактирование, инфо и создание копии через форму
  /outlays/create?copy_from=ID. Копия не сохраняется до нажатия «Сохранить»,
  получает новые ID и не переносит оплаты.
- Публичное подписание, SMS, подтверждение документов и история подписания не
  реализованы сервером. Кнопки этих действий не добавлены.
- Флаги этапов и комментарии редактируются в строках позиций на внутренней info.
  Показываются автор и время каждого поля; общие рабочие заметки вынесены под
  состав сметы. Детали: docs/backend-outlay-info-stage-gaps.md.
- PDF за период ограничен 100 сметами и 5000 позициями; серверные сообщения об
  ограничении показываются пользователю. Скачивание не разбивается незаметно.
- Кнопки документов экспортируют сохранённые данные, не текущие несохранённые
  изменения формы. Интерфейс об этом предупреждает.
- Изображения позиций берутся из images[].url, без сборки адресов storage на фронте.
  Логотип: subdivision.images[0].url (либо возвращённый logo.url/logo_url).
  Для записи по-прежнему отправляются storage-пути, а не публичные URL.
