# Журнал редактирования сметы

Реализовано сервером и подключено на фронте: GET /api/admin/outlays/{id}/audit.
Компонент OutlayAudit находится внизу формы редактирования. По умолчанию показывает
историю статусов; доступны фильтр всех действий и пагинация. Исторические авторы
и статусы выводятся из снимков API, не подменяются текущими справочниками.

## Источник требований

OldCrm/modules/admin/views/outlay/_form.php: внизу формы два блока:

1. Создание сметы: пользователь и дата; последнее редактирование: пользователь
   и дата; последнее изменение создателя: кто изменил и когда.
2. История установки статусов: пользователь, установленный статус, дата и время.

В текущем модуле Outlays этих данных/маршрута не найдено. Есть creator_id,
created_at/updated_at, а также редакторы флагов и заметок. Это другие данные.
creator_id изменяемый: его нельзя использовать как неизменяемого автора создания.

## Что добавить

Предлагаемый GET /api/admin/outlays/{id}/audit с OUTLAYS_ACCESS и проверкой доступа
к фактическому подразделению сметы. Только внутреннее API, исключить из pub.

Пример data:

```json
{
  "summary": {
    "created": {"user":{"id":1,"login":"admin"},"at":"2026-10-20 10:00:00"},
    "last_edited": {"user":{"id":2,"login":"worker"},"at":"2026-10-20 11:00:00"},
    "creator_changed": {"user":{"id":2,"login":"worker"},"at":"2026-10-20 11:00:00"}
  },
  "items": {
    "data": [
      {
        "id":10,
        "event":"status_changed",
        "user":{"id":2,"login":"worker"},
        "from_status":{"id":1,"title":"Новая"},
        "to_status":{"id":2,"title":"Собран полностью"},
        "at":"2026-10-20 11:00:00"
      }
    ],
    "current_page":1,"last_page":1,"per_page":20,"total":1,"from":1,"to":1
  }
}
```

Имена предложены для согласования. Пользователь также может содержать firstname,
lastname. Не возвращать пароли/токены. Отсутствующие события возвращать null.
История: page/page_size, стабильная сортировка по времени и ID (новые сверху).
Даты в том же часовом поясе/формате, что у остального API.

## Запись событий

- Зафиксировать неизменяемого пользователя, реально создавшего запись:
  $request->user(), независимо от выбранного в форме creator_id.
- При успешном изменении основной формы сохранять последнего редактора и время.
  Учитывать изменения состава групп/товаров, даже если поля outlays не изменились.
- При изменении creator_id фиксировать реального автора изменения, время,
  старый и новый creator_id. Не терять событие при последующей смене создателя.
- При смене status_id фиксировать старый/новый статус, пользователя и время.
  Поддержать полную форму и быстрый PATCH /{id}/status.
- Первый статус при создании можно записывать с from_status=null; отдельно
  документировать это правило, чтобы фронт показывал его как установку статуса.
- Одинаковые значения при повторном сохранении не создают ложных изменений.
- События писать в той же транзакции, что изменения. При ошибке склада или
  откате сметы запись аудита также откатывается.
- Не определять редактора только по updated_at: оно не содержит пользователя
  и может обновляться техническими операциями.
- Флаги, заметки, перевыпуск ссылки не должны автоматически подменять
  «последнее редактирование основной формы». У них свои метаданные; если нужен
  общий журнал всех действий, это отдельное расширение с явными типами событий.
- После удаления пользователя/переименования статуса журнал должен оставаться
  читаемым: снимки имени/логина и названий статусов либо другой согласованный
  механизм. FK не должны каскадно стирать историю при удалении пользователя.
- Для старых смет не выдумывать неизвестных авторов/историю. Можно показать
  известную дату создания, но неизвестный пользователь должен оставаться null.
- Проверить импорт/копирование: новая смета получает собственное событие
  создания, а не историю оригинала. Системные действия обозначать явно.

## Проверки

Создание с другим creator_id; изменение только товарной строки; смена создателя;
смена статуса обоими маршрутами; повтор сохранения без изменений; rollback при
нехватке остатка; удалённый пользователь; пагинация истории; доступ к чужому
подразделению; отсутствие аудита в публичном ответе.

После реализации фронт сможет вывести эти два блока внизу редактирования.
Сейчас заголовок формы уже использует название сметы вместо её номера.
